## Dettaglio delle modifiche

### Cartelle a tema

- `configurazione/` — stato della configurazione, guida di configurazione completa, aggiornamento
  del database, SQL integrativo.
- `guide/` — guide d'uso e di prova (app e dati reali, tutorial, test pseudo-realistico, MD1, MD3,
  icona).
- `roadmap/` — roadmap da qui al lancio, roadmap completa e le roadmap di settembre.
- `progetto/` — architettura, contratto della versione 1, modello premium e account.
- `PR/PR22-30_tessera-fedelta/` — i quattro documenti della tessera fedeltà (progetto, specifiche,
  testi legali, collaudo), nati nelle PR #22–#30. Una cartella per **serie** di PR, perché gli
  stessi documenti sono stati scritti e aggiornati da più PR (le specifiche dalla #23 alla #29, il
  collaudo nella #29 e nella #30): una cartella per ogni singola PR li avrebbe spezzati o
  duplicati. Le prossime serie di PR con i loro documenti avranno la loro cartella
  `PR/PRxx-yy_tema/`.
- `step/STEP_n/` — lo storico degli step di settembre, una cartella per step (0–7, 7.5–7.8).

### Data nel nome

- Formato `AAAA-MM-GG_NOME.md`, come il registro: in ogni cartella i documenti si ordinano per data.
- La data è quella dell'**ultimo commit che ha cambiato il documento** (`git log -1 --format=%cs`);
  lo stato della configurazione ha la data di oggi perché cambia in questa PR.
- Aggiornare solo i rimandi a un altro documento non cambia la data (altrimenti ogni rinomina ne
  provocherebbe altre a catena): per questo i documenti con i soli percorsi aggiornati in questa PR
  tengono la loro data. I documenti con la data 2026-09-27 sono quelli arrivati con il primo
  caricamento del progetto e non più cambiati.
- I file sono spostati con `git mv`: GitHub e GitHub Desktop ne mostrano la storia completa.

### Riferimenti

- Documenti, `README.md`, `CLAUDE.md` e le altre guide citano i percorsi esatti nuovi; i link
  Markdown fra documenti sono relativi.
- Codice, SQL e file di configurazione citano la **cartella** (es. «specifiche della tessera in
  `docs/PR/PR22-30_tessera-fedelta/`»): la data nel nome cambia a ogni aggiornamento, la cartella no.
- La descrizione dell'impostazione `loyalty` nella 0018 cambia solo nel testo del rimando. Su un
  database dove la 0018 è già stata eseguita resta la descrizione vecchia (la riga non viene
  riscritta): non ha effetti, è solo un testo per l'admin.
- I file di `docs/modifiche/` non cambiano: raccontano le PR passate con i nomi di allora.

### Indice e regola

- `docs/README.md` (nome fisso): tutti i documenti per cartella, con una riga di descrizione.
- `CLAUDE.md`: regola «Documenti in `docs/`» (quando un documento cambia si rinomina alla data del
  giorno con `git mv` e si aggiornano i riferimenti; nel codice si cita la cartella; documenti delle
  serie di PR in `docs/PR/PRxx-yy_tema/`) e l'indice fra i documenti da leggere per primi.

### Controllo automatico (job «Documenti» della CI)

`node .github/scripts/check_docs.mjs`, senza dipendenze, controlla:

- **nomi e cartelle:** documenti solo nelle cartelle a tema, nome `AAAA-MM-GG_NOME.md` con una data
  valida e non futura, serie di PR in `docs/PR/PRxx-yy_tema/`, step in `docs/step/STEP_n/`, registro
  `docs/modifiche/AAAA-MM-GG_prNN-titolo-breve.md`, nessun documento doppio con due date;
- **riferimenti:** in tutti i file di testo del repository ogni percorso `docs/...` esiste e nessun
  documento è citato con il nome senza data o con una data superata;
- **link:** i link relativi dei Markdown portano a file o cartelle esistenti (i blocchi di codice
  sono esclusi);
- **indice:** ogni documento è elencato in `docs/README.md`.
